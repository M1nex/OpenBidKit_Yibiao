# 投标机会数据源验证（第一步）

验证日期：2026-10-13。范围仅限现有投标机会页面指定的三个官网公开公告。本次新增只读验证脚本和本记录，没有接入产品查询界面。

## 结论

三个官网的公开公告列表、第二页和详情接口均已在当前电脑的 Electron 主进程网络环境中返回成功，无需登录账号。可以先按公开 JSON 接口实现三个独立采集适配器，暂不需要给客户端增加浏览器自动化依赖。

湖南站的半年历史查询已拿到实际公告。移动和电信的指定历史日期请求返回空结果，不能将成功响应等同于“半年公告完整可查”。历史覆盖范围仍需核对，尤其电信网站日期控件显示的是发售起止时间，与产品当前的公告发布日期筛选不能直接混用。

## 保存点与验证方式

- 开始验证前已创建检查点提交：`e787cb6`，提交说明为“投标机会数据源验证前检查点”。
- 当时源码工作区无未提交改动，因此是空检查点提交；未跟踪的 `client/release-portable/` 安装包保持原样。
- 浏览器仅用于观察官网原有的公开请求、筛选控件和详情导航。最终用项目已有 Electron 的 `net.fetch()` 直接验证，请求不带登录凭据。
- 复测脚本：`client/scripts/probe-bid-opportunity-sources.cjs`。脚本使用隔离的临时 Electron 用户目录，不读取易标的配置、工作区或 SQLite。
- 结果写入指定输出目录的 `summary.json`、各网站的 `*-evidence.json` 和 `probe.log`。完整公告响应不纳入仓库。

在 `client/` 下运行，例如：

```powershell
$probeRun = Start-Process -FilePath '.\node_modules\electron\dist\electron.exe' -ArgumentList @('scripts/probe-bid-opportunity-sources.cjs','--output','C:\Temp\yibiao-bid-source-probe','--recent-day','2026-10-12','--historical-day','2026-04-13') -WindowStyle Hidden -Wait -PassThru
$probeRun.ExitCode
```

两个日期参数明确指定查询样本；未传时使用本次验证日期样本，不代表实时日期。结束后查看输出目录中的 JSON 和文件日志。退出码 0 表示请求均成功，不表示历史数据或正文已经业务验收。

## 湖南政府采购网

当前可用入口：`http://www.ccgp-hunan.gov.cn/`。本次 HTTPS 首页连接超时，HTTP 首页和公开接口均成功。

列表：`POST /portal/category`

```json
{
  "pageNo": 1,
  "pageSize": 5,
  "categoryCode": "160-945988",
  "keyword": "物业",
  "publishDateBegin": "2026-10-12",
  "publishDateEnd": "2026-10-12"
}
```

响应成功字段为 `success`，列表位于 `result.data.data`，总数位于 `result.data.total`。日期和关键字可以分别省略。

详情：`GET /portal/detail?articleId=<编码后的articleId>&parentId=622707`。正文位于 `result.data.content`。`articleId` 含 `+`、`/` 和 `=`，必须按查询参数编码；不应拼接未经编码的 ID。

官网公开分类接口：`GET /admin/category/home/categoryTreeFind?parentId=622707&siteId=160`。采购公告为 `160-945988`，更正公告为 `160-563850`，废标/终止公告为 `160-253440`，资格预审公告为 `160-691072`。分类代码属于网站实现，应集中保存并监测变化。

列表中提供区划码、区划名、公告标题、发布时间、采购方式；预算等字段可能为空，金额单位必须以正文为依据。湖南站整体属于湖南来源，其“湖南省本级”与各市县区划不能直接当作全国省份枚举。

官网仍提供旧采购网入口，但新站已经成功查询到 2026-04-13 的公告。此次没有核对全部新旧数据覆盖，也没有扩展到其他网站。

## 中国移动采购与招标网

公开页面：`https://b2b.10086.cn/#/biddingProcurementBulletin`。

列表：`POST https://b2b.10086.cn/api-b2b/api-sync-es/white_list_api/b2b/publish/queryList`

```json
{
  "name": "",
  "publishType": "PROCUREMENT",
  "publishOneType": "PROCUREMENT",
  "purchaseType": "",
  "companyType": "",
  "size": 5,
  "current": 1,
  "creationDateStart": "2026-10-12",
  "creationDateEnd": "2026-10-12",
  "sfactApplColumn5": "PC"
}
```

`code=0` 表示请求成功；列表为 `data.content`，总数为 `data.totalElements`。省略 `publishOneType` 会混入候选人和结果等公告，不能把所有返回条目都当作正在采购的机会。

详情：同前缀下的 `POST /publish/queryDetail`，参数为列表返回的 `id`、`uuid`：

```json
{
  "publishId": "<列表id>",
  "publishUuid": "<列表uuid>",
  "publishType": "PROCUREMENT",
  "sfactApplColumn5": "PC"
}
```

正文位于 `data.noticeContent`。原文链接保留 `publishId`、`publishUuid`、`publishType` 和 `publishOneType`。`tenderSaleDeadline` 与 `backDate` 是不同时间字段，需要核对其业务含义后展示；`1900-01-01` 属于无实际日期的占位值。

公开单位字典接口为 `POST /api-b2b/api-portal/white_list_api/b2b/dict/getPortalOneDict`，官网读取 `COMPANY_CODE_TYPE` 等字典。单位中同时存在湖南、北京等省公司以及总部、研发中心、专业公司；采购单位所属标签不等同于项目实施地区。

普通 Node `fetch()` 在当前环境中出现连接失败，但系统 HTTP 客户端及 Electron `net.fetch()` 成功。客户端适配应优先复用 Electron 的网络环境，而不是据此判定官网不支持公开访问。

## 中国电信阳光采购网

公开入口：`https://caigou.chinatelecom.com.cn/`，公告查询页面为 `/search`。

列表：`POST /portal/base/announcementJoin/queryListNew`

```json
{
  "pageNum": 1,
  "pageSize": 5,
  "type": "e2no",
  "title": "物业",
  "provinceCode": "",
  "noticeSummary": "1"
}
```

`code=200` 表示请求成功；列表为 `data.pageInfo.list`，总数为 `data.pageInfo.total`。已观察到 `e2no` 对应招标公告，`cgjh10` 对应采购计划。其他公告类别仍应从官网实际控件与请求补齐，不能依据代码名称猜测。

日期参数为 `queryStartTime`、`queryEndTime`，招标公告页面控件写“发售起始时间/发售截止时间”。即使查询结果中同时包含 `createDate`，也不能未经验证把这组条件当作公告发布日期筛选。若产品按发布日期查询，需要在候选数据范围和历史覆盖确认后进行一致的本地过滤。

招标公告详情：`POST /portal/base/tenderannouncement/view`

```json
{
  "type": "TenderAnnouncement",
  "id": "<列表docId>",
  "securityViewCode": "<列表securityViewCode>"
}
```

正文位于 `data.context`。列表的 `id` 与 `docId` 是不同标识，详情使用 `docId`，并保留官网返回的查看码。采购计划详情使用 `/portal/base/purchasePlan/view`，不应让所有公告类型共用招标公告的详情入口。

## 下一阶段的工程边界

1. 三个适配器使用同一查询结果结构，但保留来源 ID、原文链接、原始公告类别、时间字段与地区信息。
2. 日期筛选明确采用公告发布日期，先处理电信日期口径和移动、电信历史数据范围。不能因历史查询返回空结果就提示“该日期没有公告”。
3. 新增查询条件后回到第一页。官网实测出现条件改变但仍停留第二页，导致总数非零而列表为空。
4. “物业类”不能只依赖标题中的“物业”，应结合公告正文和现有业务分类；“工程类”也要区分建设工程与服务项目中的工程术语。
5. 抓取失败按来源显示，不影响其他来源；与成功查询但零条结果区分。详情远程 HTML 按项目约定关闭原始 HTML 渲染。
6. 更正和终止公告独立保留，并在可确认项目关系时关联，不能按相同项目名称直接去重删除。

## 本次验证脚本问题与修复

直接启动 Windows Electron GUI 可执行文件时，调用终端可能先结束，留下验证进程继续运行。原脚本向已关闭的终端管道执行 `console.log()`，触发 `EPIPE`，Electron 因未捕获异常弹出错误窗口。

脚本已改为显式 UTF-8 文件日志，运行示例使用 `Start-Process -WindowStyle Hidden -Wait` 等待正常退出。此次问题限定于新增验证脚本，不修改正式客户端的日志、埋点或统计逻辑。
